Q: How would this run on a real BESS?

1

Measure · PLL frequency and RoCoF; SoC and power limits from the BMS; dispatch Pb0 from the EMS; PV reserve

2

Decide (every 50 ms) · Actor network proposes a residual on the tuned (Jv, Dv, α)

3

Smooth · Rate limiter, τ = 0.25 s

4

Make feasible · Headroom projection hup / hdn, always on

5

Act · Grid-forming VSG inner loops, current limiter, protection

Fallback

a = 0 is the tuned VSG. If the network or its inputs fail a check, the controller simply runs the tuned VSG with the feasibility layer.

Usable without RL

The feasibility layer works for any VSG, fixed or rule-based. It is the part a utility could adopt first.

Path

MATLAB/Simscape → HIL (if available) → pilot on a real BESS converter.

B29

Only the trained actor, the rate limiter and the feasibility layer run on the converter, as in Fig. 4.1. The inputs are signals a BESS controller already has: PLL frequency, SoC and power limits from the battery management system, the dispatch from the EMS and the PV reserve. Every 50 ms the network proposes a correction to the tuned parameters, which is smoothed and made feasible before the grid-forming inner loops see it. Because action zero is the tuned VSG, a fallback is trivial. Importantly the feasibility layer does not need reinforcement learning at all; any VSG can use it, which is the most deployable outcome. Hardware-in-the-loop is planned if facilities allow. Source: Sections 1.7, 4.2.1; Table 1.2 E6.
